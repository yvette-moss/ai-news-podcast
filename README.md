# AI News Podcast

A 100% free, personal AI-news audio digest. It reads the day's top AI
headlines, writes a short conversational script, turns it into a voice-over,
and delivers it straight to your Telegram as a playable voice message --
perfect for a morning coffee or dog walk.

**Pipeline:** RSS ingestion → Groq-hosted LLM synthesis (single call) → Microsoft
Edge TTS voice-over → ffmpeg Opus transcode → Telegram Bot API delivery.

## Features

- **Zero paid APIs required.** News comes from public RSS feeds, the script
  is written by a free-tier LLM (Groq Cloud by default, Gemini as a
  fallback), and the voice-over uses `edge-tts` (Microsoft Edge's free
  neural TTS).
- **Single-call synthesis.** All fetched articles are bundled into one
  prompt; the model picks the 5-7 most impactful stories and writes the
  full script directly. No per-article map/reduce loop, so a run costs
  exactly one LLM request -- the whole design free-tier rate limits in mind.
- **Source-diverse ingestion.** Each RSS feed contributes at most a couple
  of its latest items, so one high-volume outlet can't crowd out the rest
  once everything is pooled and capped to `MAX_ARTICLES`.
- **Written for the ear.** The script prompt explicitly avoids markdown,
  bullet points, and unpronounceable acronyms, and adds natural
  transitions between stories.
- **True Telegram voice messages, with clickable sources.** Audio is
  transcoded to mono OGG/Opus at a low bitrate (48kbps by default) and sent
  via `sendVoice`, so it renders as an actual playable voice-message bubble.
  The caption is a numbered, clickable list of the source headlines --
  measured by *visible* rendered length (not raw HTML) so it reliably fits
  in a single message.
- **Incremental, debuggable output.** `output/fetched_articles.json` is
  written right after ingestion and `output/script.txt` right after
  synthesis, so a later failure (audio/delivery) never hides what already
  succeeded.
- **Resilient by design.** If one RSS feed fails, or the LLM call hits a
  transient error, the pipeline logs it, retries with backoff where
  appropriate, and keeps going.
- **Runs anywhere.** Ships with a ready-to-use GitHub Actions workflow so it
  can run daily/weekly on a schedule without your own machine staying on.

## Quick start

### 1. Prerequisites

- Python 3.10+
- `ffmpeg` on your PATH (`sudo apt-get install ffmpeg`, `brew install ffmpeg`, etc.)
  -- required to compress audio for Telegram, and installed automatically in
  the GitHub Actions workflow.
- A Telegram bot: message [@BotFather](https://t.me/BotFather), run
  `/newbot`, and save the token it gives you.
- Your chat ID: message your new bot once, then visit
  `https://api.telegram.org/bot<TOKEN>/getUpdates` and read `chat.id` from
  the response (or message [@userinfobot](https://t.me/userinfobot)).
- A free API key for at least one LLM provider:
  - [Groq Cloud](https://console.groq.com/keys) (default, recommended), or
  - [Google AI Studio](https://aistudio.google.com/apikey) (Gemini fallback).

### 2. Install

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

### 3. Configure

```bash
python main.py --setup
```

The interactive wizard asks for your Telegram bot token, chat ID, LLM
provider + API key, and cadence (daily/weekly), then writes:

- `.env` -- local credentials (gitignored, never committed)
- `.github/workflows/{cadence}_podcast.yml` -- a GitHub Actions workflow
  pre-wired to your chosen cadence's cron schedule

Prefer to configure by hand? Copy `.env.example` to `.env` and fill in the
values yourself -- no wizard required.

### 4. Run it

```bash
python main.py --run --dry-run   # writes script + audio to ./output, skips Telegram
python main.py --run             # full run, delivers the voice message to Telegram
```

Add `--cadence weekly` to override the configured cadence for a single run.

### 5. Deploy to GitHub Actions (about 3 minutes)

1. **Fork** this repository (or push it to your own GitHub repo).
2. **Add Secrets** -- in your repo, go to **Settings → Secrets and
   variables → Actions → New repository secret** and add:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
   - `GROQ_API_KEY` (or `GEMINI_API_KEY` if you set `LLM_PROVIDER=gemini`)
3. **Enable the workflow** -- go to the **Actions** tab, enable workflows if
   prompted, then find "AI News Podcast (daily)". It runs automatically on
   its cron schedule (06:00 UTC / 08:00 CEST), or click **Run workflow** to
   trigger it immediately.

That's it -- no server, no always-on machine, no paid infrastructure.

## Configuration reference

All settings can live in `.env` locally or as environment variables /
GitHub Actions secrets in CI. See `.env.example` for the full list:

| Variable | Required | Default | Notes |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | yes | -- | From @BotFather |
| `TELEGRAM_CHAT_ID` | yes | -- | Destination chat |
| `LLM_PROVIDER` | no | `groq` | `groq` or `gemini` -- selects which API writes the script |
| `GROQ_API_KEY` | if `LLM_PROVIDER=groq` | -- | From [console.groq.com](https://console.groq.com/keys) |
| `GEMINI_API_KEY` | if `LLM_PROVIDER=gemini` | -- | From Google AI Studio; also usable as a manual fallback |
| `PODCAST_CADENCE` | no | `daily` | `daily` (24h lookback) or `weekly` (7-day lookback) |
| `GROQ_MODEL` | no | `openai/gpt-oss-120b` | Any chat model available on your Groq account |
| `GEMINI_MODEL` | no | `gemini-3.6-flash` | |
| `EDGE_TTS_VOICE` | no | `en-US-ChristopherNeural` | Any [edge-tts voice](https://github.com/rany2/edge-tts#voice-list), e.g. `en-US-AriaNeural` |
| `TARGET_BITRATE_KBPS` | no | `48` | Lower = smaller file, keep between 32-64 |
| `MAX_ARTICLES` | no | `6` | Total articles bundled into the single synthesis prompt (capped at ~1-2 per RSS feed for diversity) |
| `GEMINI_REQUESTS_PER_MINUTE` | no | `5` | Floor between retries if a call needs to be re-sent |

### A note on model availability

Free-tier model catalogs change over time -- for example, `llama-3.3-70b-versatile`
has been retired from Groq's free tier and replaced here with
`openai/gpt-oss-120b`. If `GROQ_MODEL` ever 404s with "model does not
exist," check your account's current model list at
`https://api.groq.com/openai/v1/models` and update the value.

## News sources

Five hardcoded, reliable AI-industry RSS feeds (see `podcast/feed_fetcher.py`
to add/change them): TechCrunch AI, The Verge AI, VentureBeat AI, Ars
Technica AI, and MIT Technology Review AI. Each feed contributes at most
`per_feed_limit` (default 2) of its latest items before the pool is capped
to `MAX_ARTICLES`, so headlines aren't dominated by whichever outlet
happens to publish most frequently.

## Troubleshooting

- **"ffmpeg was not found on PATH"** -- install ffmpeg; it's required for
  audio compression.
- **`model_not_found` / 404 from Groq** -- the configured `GROQ_MODEL` isn't
  available on your account; see "A note on model availability" above.
- **No articles found** -- all five feeds returned nothing in the lookback
  window (unlikely, but possible on a very quiet day, or if a feed URL
  changed). Check the logs for which feeds succeeded/failed.
- **Telegram delivery fails with 401/403** -- double-check the bot token and
  that you've sent the bot at least one message so it's allowed to message
  your chat ID.
- **Two Telegram messages instead of one** -- the headline caption only
  falls back to a separate follow-up message if the *visible* text exceeds
  ~950 characters; with the default `MAX_ARTICLES=6` this shouldn't happen.
